# Field Moves — Red v0.2.1

Обновление Surf-прототипа. Поддерживается Pokémon Red, mod API 2.
ID сохранён: surf_without_hm_red. Это замена v0.1.0, а не второй мод.

## Установка обновления

В лаунчере MODS → Import mod .zip импортируйте surf_without_hm_red-v0.2.1.zip.
Включите Field Moves - Red для Red и перезапустите игру.
Если импорт предлагает заменить старую версию, выберите замену.
При ручной установке замените main.lua, manifest.json и README_RU.md внутри
прежней папки mods/surf_without_hm_red. Не создавайте вторую копию мода.
Стандартный Windows-путь: %APPDATA%\pokemon-love2d\mods\.
У portable-сборок и при переопределении identity каталог может отличаться.

## Surf: только взаимодействие с водой

Получите HM03 и Soul Badge Коги. Возьмите команду без выученного Surf.
Подойдите к обычному доступному берегу лицом к воде и нажмите A.
Появится: The water is calm. / SURF across? с YES / NO.
YES запускает обычный Surf; NO или B отменяют действие.
После штатного текста посадки закройте текст — герой входит в воду.
В START пункта SURF больше нет. Выходите на берег обычным движением.
Разговоры с NPC, таблички, скрытые предметы и скриптовые взаимодействия
сохраняют приоритет. Недоступная вода, течения Seafoam и Cycling Road
не вызывают предложение плавать. В уже начатом плавании оно не появляется.

## Fly: отдельный пункт START

Получите HM02 и Thunder Badge лейтенанта Сёрджа. Учить Fly не требуется.
Откройте START → FLY: появится родная карта перелётов Red.
Выберите посещённый город стрелками и нажмите A; B закрывает карту.
Движок выполняет штатный перелёт. В помещении пункт сообщает Can't FLY here!
Пункт появляется после получения HM02 и значка. Непосещённые города
и недопустимые точки исключает штатная карта; API проверяет выбор повторно.

## Общие правила

Команда должна быть непустой. Для полевой способности используется первый
покемон команды независимо от вида, совместимости с HM и HP. Если кто-то
уже знает соответствующий приём, он имеет приоритет. Приёмы и PP не меняются.
Получение HM подтверждается сюжетным флагом или предметом в инвентаре:
SURF — EVENT_GOT_HM03 / HM_SURF + SOULBADGE;
FLY — EVENT_GOT_HM02 / HM_FLY + THUNDERBADGE.
После обычного получения HM можно хранить в PC, способность останется доступной.
Другие полевые приёмы мод не меняет. Мод не добавляет собственных данных в save.

## Проверка

Сверено с исходниками gen1recomp dev, commit
 e2114f7c85795d52903ea98deab493a4f181bace.
Локально пройдены 33 проверки под LuaJIT 2.1: доступ, приоритет взаимодействий,
родные TextBox и ChoiceBox, подтверждение и отмена Surf, ограничения воды,
родная TownMap, фильтрация посещённых городов, выполнение WorldAPI, manifest.
Использованы синтетические данные, заглушка LÖVE и контрольные вызовы вместо
анимаций Surf/Fly. ROM, визуальная отрисовка и настоящий перелёт по карте
здесь не запускались. Предыдущая v0.1 проверена пользователем в игре;
новые взаимодействие и Fly требуют такого же игрового прогона.

Для быстрой проверки: A у воды → NO, затем A → YES; разговор с NPC;
отсутствие SURF в START; START → FLY → B; затем перелёт в посещённый город.
Проверьте отдельно сохранения без нужного HM или значка.
Для отключения выключите мод и перезапустите игру; удобно сделать это на берегу.

## Проверенные интерфейсы

- game.ready — получение объекта игры;
- world.interacted, kind == none — A без обработанного обычного взаимодействия;
- fieldmove.eligibility — доступ к SURF и FLY без обучения;
- availableFieldActions / useFieldAction — контекстный Surf;
- TextBox.new(..., {choice=...}) — штатное YES/NO;
- ui.start_menu.items — пункт FLY;
- mod.ui.push(game, "TownMap", {fly=true, onFly=...}) — родная карта;
- canFly / flyTo — штатный перелёт с проверками.

## Исправление v0.2.1: совместимость с Quality of Life

Проверена установленная Quality of Life 1.3.0:
репозиторий unxpected-uxp/pokemon-gen1-recomp-mod-qol.
Её меню SURF / USE GOOD ROD / CANCEL и наш текст SURF across? запускались
по одному событию world.interacted. Наш запрос мог открыться первым, после
чего QoL открывал своё меню поверх него, не проверяя занятость экрана.
Выбор Surf запускал посадку, но наш старый вопрос оставался под меню.
Это конфликт обработчиков, а не повторное предложение оригинальной Red.

Наш обработчик теперь выполняется после обработчика QoL (приоритет -100).
Если QoL открыл меню или начал посадку/рыбалку, штатный availableFieldActions
возвращает пустой список и второй запрос не создаётся.

При включённых водных взаимодействиях QoL остаётся его меню выбора.
Если они выключены, наш мод по-прежнему предлагает SURF across? → YES / NO.
Fly и требования HM/значков сохраняются. Настройки QoL мод не меняет.

До исправления конфликт воспроизведён локально. После изменения пройдены
54 проверки совместимости с настоящим модулем Easy Interactions из
установленной QoL 1.3.0: оба порядка загрузки, SURF FIRST, FISH FIRST,
SURF ONLY, OFF, отмена, рыбалка, посадка и повторное A во время плавания.
Также повторно пройдены 33 проверки Surf/Fly. Анимации заменены контрольными
вызовами; обновление требует проверки в запущенной игре.

После обновления полностью перезапустите игру, чтобы убрать уже открытые
старой версией окна. На берегу нажмите A → SURF: после текста посадки
не должно быть второго вопроса. Проверьте также CANCEL и USE GOOD ROD.
